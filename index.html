BOQ / Accomplishment

—

Original Amount = Original Quantity × Unit Cost. Revised Amount = Revised Quantity × Unit Cost. Additive, Deductive and Extra Work are locked and calculated automatically from the difference between the two amounts (a pay item with no original amount is Extra Work), so Original + Additive − Deductive + Extra Work always equals Revised. Item Weight % = Revised Amount ÷ Revised Contract Amount, Weighted Accomplishment % = Item Weight % × Physical Accomplishment %, and Cumulative % = Previous % + This Period % — no value is typed twice. One monthly record is kept per pay item and reporting period; earlier months are never overwritten.

Project Details

Data & Storage

This module writes only to ProjectAccomplishmentProjects, ProjectAccomplishmentItems, ProjectAccomplishmentPeriods and ProjectAccomplishmentSettings. The BOQ / Variation Order integration adds columns to those same tables — contract ID, unit, original and revised quantities, unit cost, original and revised amounts, the additive / deductive / extra work columns and every pay item's monthly history. Every submitted project also gets its own BOQ sheet tab (named after the project id) whose header row is created with the project and whose rows mirror the Contract Items on every save. It never reads or writes Material Input, On-Site Inventory, Balance Search or Inventory Reports data.

📝 PDM Schedule — Activity Data Entry

The contract items drive the schedule: pick a contract, type the four schedule fields per item, everything else is calculated.

Activity Data Entry — Contract Items

—

The contract items are loaded from the Project Accomplishment module for the contract selected in the toolbar — item, description and both totals are never typed here. Enter only Early Start Date and Late Start Date: Duration = Late Start − Early Start + 1 (both dates counted — February 1 to October 17, 2025 is 259 calendar days), both finishes, the float and the critical flag are calculated automatically, and the Activity Table below picks that duration up from this entry.

⏸️ PDM Suspension Orders & Resumption

Suspension orders are applied to the PDM scheduling engine as a calendar — durations, relationships, lag, float and the critical path are recalculated automatically, never hand-edited.

Project Status: — PDM suspension store

Suspension Order

New order

Leave the Resumption Date blank for an indefinite suspension: the project status becomes SUSPENDED, every unfinished activity scheduled on or after the suspension date (and everything that depends on it) is marked ON HOLD, completed work keeps its actual dates and progress, and no dates are generated past the suspension until an authorized resumption date is recorded.

Suspension Orders

—

Unlimited suspension and resumption orders per project. Overlapping orders are merged once (no double counting) and flagged for review; duplicate order numbers and invalid date ranges are rejected before they can reach the schedule.
